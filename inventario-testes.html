Visão geral

O repositório automatiza chamadas HTTP à ServeRest; não contém a implementação do servidor. Os casos abaixo são cenários existentes, não sugestões nem resultados de execução.

56casos descobertos (1 opt-in)
8arquivos de teste
5casos @smoke
4casos @critical
16operações no cliente HTTP

Como interpretar: npx playwright test --list descobre os casos, mas não os executa. Contagem de operações utilizadas não é cobertura de código nem prova de cobertura total dos requisitos ou da API. As tags são sobrepostas: não some os seus totais.

Estrutura e organização

Cliente HTTP

src/api/serverest.ts organiza usuários, login, produtos e carrinhos. Retorna respostas para asserções nos testes; os contratos de sucesso ficam em src/tipos.ts.

Massa e pré-condições

src/dados/fabrica.ts gera dados únicos. src/fixtures.ts fornece usuários, produtos, cliente HTTP e limpeza de carrinhos, produtos e usuários.

Verificações

src/dados/mensagens.ts centraliza mensagens; src/verificacoes.ts reúne verificações reutilizadas, como estoque e leitura do JWT.

Suítes

tests/ agrupa fluxos de compra, regras, integridade e usuários. tests/smoke/ reúne verificações rápidas por recurso.

Configuração e CI

playwright.config.ts define URL, workers, retries e relatórios. testes-api.yml define smoke, shards, execução agendada e relatórios.

Análise e oportunidades

Pontos fortes

  • Responsabilidades separadas: cliente, tipos, dados, fixtures e verificações.
  • Massa única por execução e limpeza ordenada; falhas persistentes de limpeza são registradas.
  • Validação de estado após ações, incluindo estoque e isolamento entre clientes.
  • CI prevê instância local isolada por job e investigação de cenários críticos sem retry.

Candidatos para ampliar

  • Ampliar os valores-limite e formatos de campos de entrada.
  • Verificar tokens expirados e autorização de outras operações protegidas.
  • Investigar a corrida observada na ServeRest local durante compras concorrentes.

São oportunidades identificadas na suíte, não requisitos confirmados nem casos já implementados.

Limites e riscos

  • O serviço público compartilhado pode sofrer reset, 429 ou interrupções em execuções locais.
  • A cobertura de operações não mede caminhos internos do servidor, que não está neste repositório.
  • O teste simultâneo é opt-in e pode não provocar a corrida em toda execução; não roda na CI padrão.
  • Como a limpeza não altera o resultado do teste, seus avisos devem ser acompanhados no relatório.

Execução e fontes

npm test executa a suíte; npm run test:smoke, npm run test:critical e npm run test:regression filtram por tag. Localmente a URL padrão é https://serverest.dev; BASE_URL permite usar outro ambiente. Consulte o README e a pipeline para detalhes.

Fontes: arquivos de tests/, cliente e fixtures em src/, configuração Playwright, pipeline e descoberta com npx playwright test --list. Este documento é uma fotografia manual; execute novamente a descoberta após mudanças na suíte.
